### 11. 怎样设计微服务注册中心

**当时回答与评分：1/10。** 08:00 将问题理解成配置中心。面试官在 08:02 明确提到服务注册和发现，随后转向配置中心，转录中没有形成注册中心设计回答。这一分数评价本次回答展示出的内容。

**问题分析：** 注册中心维护服务名称与实例地址之间的关系，并管理实例的可用状态。需要说明实例怎样加入、调用方怎样发现、实例异常时怎样更新列表。

**参考回答：** 我会维护服务到实例列表的关系，每个实例包含服务名、实例标识、地址、端口、环境和必要的元数据。服务启动后提交注册信息，通过续约或连接状态表明自己仍然可用；服务退出时主动注销。注册中心结合健康检查管理实例状态，超过规定时间没有续约的实例会被标记不可用或删除。调用方查询或订阅服务列表，在本地选择实例并发起调用。实例变化需要通知订阅方，客户端还要处理重新连接和列表刷新。多个注册中心节点之间要明确数据同步和网络异常时的行为，防止调用方长期使用过期地址。

**技术补充：** 心跳方式取决于协议和实现。例如 Nacos 的 HTTP 客户端可以使用心跳续约，gRPC 客户端通过连接生命周期维护临时实例；实例健康状态和是否允许接收请求也可以分别管理。参考：[Nacos 实例健康与元数据说明](https://www.nacos.io/en/docs/next/manual/user/naming/health-and-metadata/)。

**改进要求：** 能够从服务启动到一次 RPC 调用完整说明注册、发现、选择实例和请求失败后的处理。需要补习服务注册、服务发现、健康检查、本地缓存、负载均衡及服务治理的基本关系。

### 12. 怎样设计配置中心

**问题分析：** 设计配置中心需要从配置的生命周期出发：谁编辑、怎样验证、如何发布、哪些应用读取，以及出现问题时怎样处理。数据一致性需要结合具体范围说明。

**参考回答：** 我会按照应用、环境和 namespace 标识配置资源，分别管理配置内容、版本、发布状态和操作权限。编辑内容经过格式和业务校验后才能发布，发布记录需要保存版本、操作人和时间。发布成功后通知订阅客户端，客户端获取配置并应用到业务对象。对于并发编辑，可以校验当前版本，防止覆盖他人的修改。对于多实例应用，服务端记录发布状态，客户端报告接收和应用状态，便于确认哪些实例已经生效。异常配置需要能够停止发布或重新发布经过验证的版本。

**技术补充：** Nacos 将发布、查询和监听定义为不同动作，配置资源通过 namespace、group 和 dataId 标识。客户端收到变化后，还需要获取并应用配置内容。参考：[Nacos 配置发布、查询与监听](https://www.nacos.io/en/docs/next/manual/user/config/publish-query-listen/)。

### 15. Redis 主从切换时分布式锁是否安全

**当时回答与评分：2/10。** 12:24 回答涉及给锁设置有效期，面试官在 12:28 明确指出关注的是 Redis 高可用模式。转录中的 12:12 短句识别不清，不据此评价态度。能够确认的缺口是没有回答复制和主节点切换对锁安全的影响。

**问题分析：** 面试官使用了“原子性”一词，结合主从和 Sentinel 场景，按对话推断是在追问分布式锁的互斥安全。`SET ... NX` 在一个 Redis 实例上的条件写入具有原子性；主节点切换时，锁记录可能尚未复制到被提升的副本。

**参考回答：** 不能保证每次主从切换都保持互斥。客户端 A 在主节点上成功获取锁后，锁记录可能还没有复制到副本，主节点就发生故障。副本被提升为新主节点时没有这条记录，客户端 B 就可能再次获取同一个锁，而 A 仍然继续执行任务。此时两个客户端都可能操作同一资源。设置过期时间用于限制锁的存活时间，这个故障过程仍然需要另外考虑。Redis 的默认复制是异步复制，`WAIT` 能增加已确认的副本数量，其保证也需要结合故障和持久化条件理解。参考：[Redis 复制说明](https://redis.io/docs/latest/operate/oss_and_stack/management/replication/)。

**锁使用的补充：** 获取锁时，可以通过 `SET lockKey ownerToken NX PX ttlMillis` 一次完成条件写入和有效期设置。释放锁需要原子检查 `ownerToken` 并删除对应记录，例如使用 Lua。处理时间超过有效期以后，旧持有者可能继续执行；重要写入可以配合由可靠协调机制生成的 fencing token，由被保护的存储拒绝过期持有者的操作。参考：[Redis 分布式锁说明](https://redis.io/docs/latest/develop/clients/patterns/distributed-locks/)。

**改进要求：** 能够讲清楚单实例命令原子性、复制、故障切换、有效期、续约、释放锁和业务幂等分别承担什么作用。为重要业务选择锁方案时，需要明确可以接受哪些故障结果，并说明数据层怎样保障业务正确性。
