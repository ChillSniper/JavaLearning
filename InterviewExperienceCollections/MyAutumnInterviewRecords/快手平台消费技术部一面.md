**参考设计：指标定义。**以“识别风险案件”为正类：

- `TP`：实际有风险，系统识别为风险。
- `FP`：实际正常，系统识别为风险。
- `FN`：实际有风险，系统判断为正常。
- `TN`：实际正常，系统判断为正常。
- `Accuracy = (TP + TN) / (TP + FP + FN + TN)`，表示全部判断中正确的比例。
- `Precision = TP / (TP + FP)`，表示被识别为风险的案件中，确有风险的比例。
- `Recall = TP / (TP + FN)`，表示全部真实风险案件中，被系统识别出来的比例。

这些指标需要同时说明正类、样本范围和阈值；类别数量悬殊时，整体 Accuracy 容易掩盖风险识别问题。指标定义参见 [Google 分类评测说明](https://developers.google.com/machine-learning/crash-course/classification/accuracy-precision-recall)。

**参考设计：达到线上可用需要回答的内容。**

1. **数据与标签。**按照时间、区域、案件类别组织脱敏样本，防止同一案件或重复材料同时进入调试集合与独立测试集合；检查人工结论是否经过复核。用于调整 Prompt、规则和阈值的样本应当与最终测试样本分开。
2. **评测对象。**分别评估 OCR、材料真实性、信息比对和端到端审核。某个子步骤效果良好，仍需要确认整个自动处理链路的业务结果。
3. **人工转交。**材料缺失、来源冲突、工具失败、结果无法判定时，进入明确的人工审核状态。统计 `自动处理覆盖率 = 自动完成处理的案件数 / 符合统计范围的案件总数`，并单独评估自动放行结果与自动拒绝结果的正确性。
4. **业务门槛。**依据误放风险案件和误拒正常案件的成本，确定各类别准入条件。具体门槛由业务要求和评测数据决定，本次转录没有可以引用的门槛数值。
5. **线上验证。**记录规则、Prompt、模型和工具版本；通过影子运行或限定范围的发布观察结果，并保留人工抽检、异常告警和停止自动处理的能力。关注正确性、覆盖率、处理耗时、单案成本与人工复核结果。

**改进与练习：**准备一份实际可复核的评测记录，必须包含样本范围、标签规则、混淆矩阵、转人工数量、版本信息和失败案例。能够解释每个指标的分子、分母，以及它对应的业务风险。

### 6. 可恢复 DAG 执行引擎如何实现？checkpoint 如何支持恢复？

**时间与证据：**10:10—10:55，P0060—P0061。

**你的回答与评分：3/10。**说明了保存 checkpoint 和后续状态到 SQLite，并能够从数据库读取历史状态。这回答了部分持久化位置和用途。

**参考回答：**

> 可恢复执行需要保存任务进度和节点执行结果。恢复时根据持久化状态确定已经完成的节点，以及仍需要执行的节点，再依据依赖关系继续调度。保存到 SQLite 的内容需要足以作出这个判断。
>
> 对已经成功并提交结果的节点，复用保存的输出；对于中断时仍在执行的节点，需要检查执行权是否有效，以及外部动作是否已经产生结果。调用外部服务后，进程可能在保存结果之前中断，因此还需要幂等标识或查询确认，才能控制重复执行。

**参考设计：应当保存的数据。**

- `run_id`、`workflow_version`、输入版本与运行状态。
- 每个节点的 `node_id`、依赖关系、状态和输入引用。
- 成功节点的输出或输出文件引用、校验信息。
- `attempt`、错误原因、执行者和执行权有效期。

### 9. 在浏览器输入一个域名，到返回页面结果，完整流程是什么？

**时间与证据：**13:32—16:37，P0096—P0115。具体域名识别不清，按一般网页访问问题回答。

**参考回答：**

> 以首次访问 HTTPS 网站、使用基于 TCP 的 HTTP、没有可复用连接为例：浏览器解析 URL，确认目标主机和请求路径；查询 DNS 得到 IP 地址；建立 TCP 连接，再进行 TLS 协商和服务器身份验证；发送 HTTP 请求。请求到达服务端后，由相关服务处理并返回状态、响应头和内容。浏览器解析 HTML、CSS 和 JavaScript，获取需要的资源，完成布局、绘制和合成，显示页面。

**关键机制与条件：**

1. **URL 与缓存。**浏览器识别协议、主机、端口、路径和查询参数，并结合缓存策略判断资源是否可以直接使用，或需要发送条件请求。
2. **DNS。**查询通常涉及浏览器或操作系统缓存、配置的递归解析器。递归解析器在缓存无法回答时，按需要访问根、顶级域和权威 DNS，取得地址并按 TTL 缓存。具体路径也受浏览器 DNS 设置等条件影响。
3. **传输与安全。**使用 TCP 时通过 `SYN`、`SYN-ACK`、`ACK` 建立连接；HTTPS 还需要 TLS 协商，包含验证证书和建立加密通信所需的信息。已有连接可能复用。HTTP/3 使用基于 UDP 的 QUIC，其连接过程需要按该协议说明。
4. **本地链路与路由。**对于 IPv4，以 ARP 获取本地下一跳的 MAC 地址，再发送链路层数据帧；不同网络之间通过路由转发 IP 数据包。IPv6 使用 NDP 完成相关邻居发现。该过程服务于网络通信，在实际需要发送数据时发生。
5. **HTTP 与服务端。**请求携带方法、路径、请求头及可能存在的请求体，可能经过 CDN、负载均衡和反向代理。服务端依据业务处理请求，返回状态码、响应头和响应体，也可能要求重定向。
6. **浏览器渲染。**浏览器构建 DOM 和 CSSOM，执行相关 JavaScript，完成样式计算、布局、绘制与合成。HTML 和资源可以边接收边处理，脚本和样式的加载方式会影响执行顺序。

浏览器页面获取与渲染流程参见 [MDN 浏览器工作过程](https://developer.mozilla.org/en-US/docs/Web/Performance/Guides/How_browsers_work)。上述 DNS、链路和协议版本说明用于补全后端面试常见追问。

**改进与练习：**独立完成一次浏览器 Network 记录与 DNS 查询，解释记录中的 DNS、连接、TLS、首字节等待和内容下载时间。准备 90 秒口述，并能够回答“已有连接是否握手”“跨网络访问时 ARP 查找谁”“HTML 到达后如何显示”三个追问。

## 急需改进的地方

### 1. 能够解释并演示项目核心机制

**关联问题：**第 6、7、8 题，得分分别为 3、4、2 分。

**紧迫原因：**简历介绍了多角色、DAG 和可恢复执行，面试官随即追问具体机制。这些能力需要能说明状态保存、执行调度和结果合并。

**必须补充：**

- 当前模型请求的输入如何组装，子 Agent 分别接收什么。
- 原始资料、分析结果和共享信息保存在哪里。
- checkpoint 记录哪些数据，进程重新启动后如何确定待执行节点。
- 并行节点如何合并结果，外部调用成功后本地中断如何确认状态。
- 实际项目中哪些对象是独立 Agent，哪些是固定流程节点和 Tool。

**练习与完成标准：**对当前项目选择一条真实任务，逐项展示模型输入、节点记录和输出引用；主动中断进程并重新启动，核对已完成结果复用、未完成节点继续执行和外部动作记录。用五分钟讲清楚全过程，所有实现描述都能够找到对应代码或运行证据。

### 2. 准备一项有完整评测证据的个人改进

**关联问题：**第 2、3、5、13 题。

**紧迫原因：**这是面试官明确表达的能力要求。当前回答能够列出功能和角色，尚未清楚展示本人如何通过修改提升结果。

**必须补充：**业务目标、技术指标、原始结果、失败案例、个人改动、相同测试口径下的新结果，以及成本和耗时变化。准确率、精确率、召回率、自动处理覆盖率需要分别定义。

**练习与完成标准：**选择本人实际能够修改和验证的一个问题，保存固定测试集合、标注依据、版本和真实运行输出。完成前后版本比较，说明改善了什么、仍有哪些错误、业务上有什么意义。没有测量过的指标保留为空，不补写数字。

### 3. 把网络基础组织成能够连续解释的过程

**关联问题：**第 9 题，3/10。

**紧迫原因：**本题只有一道，但覆盖 DNS、连接建立、加密、HTTP 和浏览器处理。回答中已有多个名词，需要进一步理解各步骤如何连接。

**必须补充：**递归解析器与权威 DNS 的分工、TCP 与 TLS 的先后条件、下一跳 MAC 地址、HTTP 请求响应、连接复用、浏览器渲染。

**练习与完成标准：**完成一次真实 DNS 查询和浏览器访问记录，能够用 90 秒说明完整流程，且能够继续回答第 9 题末尾的三个追问。解释中明确首次访问、缓存命中和连接复用分别改变了哪些步骤。

### 4. 让每项经历都有清楚的个人职责和一个完整案例

**关联问题：**第 1、2、4、5 题。

**紧迫原因：**介绍整体业务占用了较多时间，个人完成的内容需要面试官继续寻找。上游团队提供的 Agent 与本人完成的规则、接入及处置流程，需要清楚说明各自职责。

**必须补充：**本人负责模块、输入输出、关键设计、遇到的一个问题、处理措施和验证结果。包名、区域名、状态名从实际代码核对。

**练习与完成标准：**准备 90 秒的实习项目说明和 90 秒的个人项目说明。每个项目配一个可以深入五分钟的案例，能够具体回答“这一部分谁完成”“为什么这样设计”“如何确认有效”。

### 5. 在规定时间内形成能够检查的现场结果
