**参考回答：** 我维护闭区间 `[left, right]`，保证最小元素的下标始终位于其中。比较 `nums[mid]` 与 `nums[right]`：如果前者更大，说明最小值位于 `mid` 右侧，更新 `left = mid + 1`；否则最小值位于包含 `mid` 的左侧范围，更新 `right = mid`。循环条件使用 `left < right`，区间每次严格缩小，结束时返回 `left`。时间复杂度为 `O(log n)`，额外空间为 `O(1)`。

对于练习示例，初始 `left = 0`、`right = 6`、`mid = 3`，数值 7 大于右端数值 3，更新 `left = 4`；接着 `mid = 5`，数值 2 小于右端数值 3，更新 `right = 5`；随后 `mid = 4`，数值 1 小于右端数值 2，更新 `right = 4`，最终返回 4。两个元素 `[2, 1]` 时，`mid = 0`，一次更新后返回 1。

```java
public class Solution {
    public int minIndex(int[] nums) {
        if (nums == null || nums.length == 0) {
            throw new IllegalArgumentException("nums 不能为空");
        }

        int left = 0;
        int right = nums.length - 1;
        while (left < right) {
            int mid = left + (right - left) / 2;
            if (nums[mid] > nums[right]) {
                left = mid + 1;
            } else {
                right = mid;
            }
        }
        return left;
    }
}
```

如果允许重复元素，`nums[mid] == nums[right]` 时无法按上述条件确定方向，可以增加 `right--` 分支以查找某个最小值下标，最坏复杂度会达到 `O(n)`。多个最小值存在时，“任意最小值下标”“第一个最小值下标”和“下降位置”需要分别确认。例如 `[0, 1, 0]` 的第一个最小值下标为 0，下降位置为 2。

**改进动作：** 这是最急需训练的内容之一。开始编写前明确输入、输出与重复元素条件，用一句话说出区间不变量；完成后检查单元素、两个元素、未旋转、不同旋转位置与变量名称一致性，再运行代码。
