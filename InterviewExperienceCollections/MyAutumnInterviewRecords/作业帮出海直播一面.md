**练习解法的明确约定：** 以下代码接受 `[+-]?[0-9]+(\.[0-9]+)?`，返回 `double`；整数部分至少一个数字，有小数点时小数部分至少一个数字；非法输入抛出 `IllegalArgumentException`。该规则用于复习练习，原始题目的完整规则无法从转录恢复。按面试官要求，不处理数值溢出。

```java
public final class DecimalParser {
    public static double parseDecimal(String text) {
        if (text == null || text.isEmpty()) {
            throw new IllegalArgumentException("Empty input");
        }

        int index = 0;
        int sign = 1;
        char first = text.charAt(0);
        if (first == '+' || first == '-') {
            sign = first == '-' ? -1 : 1;
            index++;
        }
        if (index == text.length() || !isDigit(text.charAt(index))) {
            throw new IllegalArgumentException("Missing integer digits");
        }

        double value = 0.0;
        while (index < text.length() && isDigit(text.charAt(index))) {
            value = value * 10.0 + (text.charAt(index) - '0');
            index++;
        }
        if (index < text.length() && text.charAt(index) == '.') {
            index++;
            if (index == text.length() || !isDigit(text.charAt(index))) {
                throw new IllegalArgumentException("Missing fractional digits");
            }
            double factor = 0.1;
            while (index < text.length() && isDigit(text.charAt(index))) {
                value += (text.charAt(index) - '0') * factor;
                factor *= 0.1;
                index++;
            }
        }
        if (index != text.length()) {
            throw new IllegalArgumentException("Invalid character");
        }
        return sign * value;
    }

    private static boolean isDigit(char ch) {
        return ch >= '0' && ch <= '9';
    }
}
```

**循环不变量：** 整数循环开始时，`value` 表示已经读取的整数前缀；小数循环开始时，`value` 包含已经读取的小数位，`factor` 对应下一个小数位的权重。`index` 始终指向下一个待处理字符。

**用例与实际验证：**

- 合法输入覆盖 `0`、`+0`、`-0`、正负整数、`+12.34`、`0.5`、`001.20` 和较长小数。
- 非法输入覆盖 `null`、空字符串、单独符号、单独小数点、`.5`、`1.`、多个小数点、中间符号、空白、科学计数法、`NaN` 和全角数字。
- 本地执行了 Java 编译，启用 `-Xlint:all -Werror`；运行了固定用例、长度不超过五的有限字符集穷举，以及 10,000 个随机合法输入。
- 共验证 10,241 个合法输入和 9,118 个非法输入。合法输入以 `BigDecimal.doubleValue()` 为独立参考，允许 `max(1, |expected|) × 10^-12` 的浮点误差；非法输入的期望由练习规则判定，另行检查负零。

### 7. 红黑树的特点与链表转换条件

**现场回答与评分：4/10，包含第 8 题。** 你知道链表过长会影响查询，也提到了 `8` 和 `64`。转录中的表达把数组容量与链表长度对应混淆了，红黑树本身的性质没有展开。

**分析：** 面试官同时在检查数据结构基础和 ConcurrentHashMap 的具体规则。需要解释树的高度如何受到约束，再说明哈希冲突较多时树形结构的价值。

**参考回答：**

> 红黑树是一种自平衡二叉搜索树。节点具有红黑两种颜色，根节点和 NIL 叶节点为黑色，红色节点的子节点必须为黑色，从同一节点到各个 NIL 叶节点的路径具有相同数量的黑色节点。这些约束使树的高度保持在 `O(log n)`。
>
> 当哈希冲突使同一位置的链表变长时，沿链表查找的成本会增长。转换为红黑树可以利用树的高度约束改善这类查询。
>
> 在 JDK 8 的 ConcurrentHashMap 中，`TREEIFY_THRESHOLD` 为 `8`，`MIN_TREEIFY_CAPACITY` 为 `64`。`64` 对应数组容量。数组容量不足时通常通过扩容处理；容量满足要求且达到相应节点计数条件时，才尝试树化。常见 `putVal` 路径中，已有至少八个节点后继续插入，会触发相关检查；精确计数应结合具体方法说明。

**改进：** 将“红黑树性质”“查询成本”“数组容量”“节点计数”分别讲清楚。标准红黑树的复杂度与特定 Map 在特殊键比较条件下的行为，需要分别判断。
