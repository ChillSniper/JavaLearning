### 26. 主任务停止后怎样取消多个 goroutine

**现场回答与评分：2/10。** 23:59—25:23，你提到了 channel 和 WaitGroup，在面试官提示上下文传播之后表示理解。没有独立说出 context 的标准用法，也没有明确 WaitGroup 负责等待完成、取消需要任务主动响应。

**分析与改进：** 需要准确表达取消的传播方向：父 context 取消可以传到派生 context，子任务自身取消通常只影响相应分支。进程直接退出时无法保证清理工作完整执行。

**参考回答：** 我会创建可取消的 context，传给所有子任务和下游调用；主任务结束或收到停止信号时调用 cancel。子任务通过 select 监听 ctx.Done()，退出循环并释放资源，再调用 WaitGroup.Done；主任务通过 WaitGroup.Wait 等待它们结束。取消是协作式机制，任务必须主动响应，阻塞调用也需要支持 context 或超时。[Go Context](https://go.dev/blog/context)

```go
package main

import (
    "context"
    "fmt"
    "sync"
)

func main() {
    ctx, cancel := context.WithCancel(context.Background())
    defer cancel()

    var wg sync.WaitGroup
    ready := make(chan struct{}, 3)
    for i := 0; i < 3; i++ {
        wg.Add(1)
        go func() {
            defer wg.Done()
            ready <- struct{}{}
            <-ctx.Done()
        }()
    }
    for i := 0; i < 3; i++ {
        <-ready
    }
    cancel()
    wg.Wait()
    fmt.Println("all workers exited")
}
```

代码仅展示取消与等待的关系；实际业务循环还需要在等待任务和执行 I/O 的位置响应 context。

### 29. 大文件中找最大的 K 个数

**现场回答与评分：6/10。** 31:17—32:53，你独立提出容量为 K 的最小堆，能够解释填充、比较堆顶和替换，核心方向正确。你复述内存为 4 GB，随后提出一次读取 5 GB，容量约束存在冲突；最终把这一过程称为归并排序，算法名称与描述的过程不一致。转录没有保留实现代码，本题按思路评分。

**分析与改进：** 只求 Top K 时，可以流式读取整个文件并持续维护一个堆。先确认是否保留重复数值、是否需要排序输出，以及文件数字格式。面试官提到归并时，也需要依据自己描述的实际步骤判断算法名称。

**参考回答：** 如果只求最大的 K 个数，而且 K 个元素能够装入内存，我会用流式读取加容量 K 的最小堆。堆未满时插入，堆满后只在新数值大于堆顶时替换。每读完一部分数据，堆中保存当前已经读取的数据中的最大 K 个值。读取结束后，如需降序输出，再对这 K 个值排序。时间复杂度为 O(N log K)，额外空间为 O(K+B)，B 为受限读取缓冲区。输入包含相同数值时按出现次数保留；若要求不同数值，需要补充去重规则。只有要求所有数据完整排序时，才需要讨论外部排序。K 自身无法装入内存时，也需要外部处理方案。

以下代码假设文件包含以空白分隔的合法 long long 整数，重复值分别计数：

```cpp
#include <algorithm>
#include <functional>
#include <istream>
#include <queue>
#include <vector>

std::vector<long long> topK(std::istream& input, std::size_t k) {
    if (k == 0) {
        return {};
    }
    std::priority_queue<long long, std::vector<long long>,
                        std::greater<long long>> heap;
    long long value;
    while (input >> value) {
        if (heap.size() < k) {
            heap.push(value);
        } else if (value > heap.top()) {
            heap.pop();
            heap.push(value);
        }
    }
    std::vector<long long> result;
    while (!heap.empty()) {
        result.push_back(heap.top());
        heap.pop();
    }
    std::reverse(result.begin(), result.end());
    return result;
}
```

第 24—26 题连续需要补充或提示。你有 Go 服务端实习经历，面试官会自然期待你能解释 G、M、P，以及日常服务中怎样取消任务、传递超时和等待退出。

练习要求：独立写出使用 context 取消多个 goroutine 的程序，说明 cancel、ctx.Done、WaitGroup 各自的作用；能解释系统调用阻塞时 P 怎样继续服务其他任务；能说明 work stealing 改善什么问题。完成标准是代码运行成功，并能够解释每一步的退出条件。

### 优先级 P0 理解分布式锁与业务幂等

第 16—18 题没有完整说明同一业务请求先后重复执行、锁过期后的旧执行者、数据库条件更新和外部动作结果未知这几类情况。

练习要求：用“同一玩家的同一轮 CRM 召回”说明幂等键、唯一约束、处理中与成功状态、外部调用超时后的确认过程。画出或写出两次请求先后进入、两个执行者同时工作时的状态变化。能够指出实际项目完成了哪些措施、哪些只是补充设计。

### 优先级 P0 用明确的插入示例解释间隙锁

第 13、14 题中，修改已有数据与新增匹配记录没有区分清楚。

练习要求：使用有索引的范围查询举例，分别说明已有记录更新、向间隙插入、普通一致性读取和 FOR UPDATE。能够说出隔离级别与唯一等值查询的条件，详细锁范围以执行计划和实际锁信息确认。

### 优先级 P1 为可恢复工作流准备一次中断续执行证据

第 20 题主要解释了历史过程读取。恢复能力需要说明节点状态如何保存、从何处继续、外部工具已经成功但 checkpoint 未保存时怎样处理。

练习要求：选择实际项目中的一个节点，在执行前、执行后与状态保存前后分别中断程序，记录重启后执行了哪些步骤。只把测试已经证明的行为写入项目能力描述。

### 优先级 P1 直接衡量同步质量并检查资源上限

第 21 题需要使用同步延迟、失败数量和数据核对说明一致性；第 29 题需要在开始推导时记录内存上限。

练习要求：把查询响应时间、同步延迟和补偿完成时间分别定义；为 Top K 写出缓冲区与堆的内存预算。听到面试官提示时，继续根据实际步骤判断算法名称和适用条件。
