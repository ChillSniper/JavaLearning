**参考回答：**

这里采用从 1 开始的闭区间 `[left, right]` 作为练习题条件。创建哨兵节点 `dummy`，找到区间前驱 `before`、区间起点 `start`、区间终点 `end`，并保存区间之后的节点 `after`。将 `end.Next` 设为 `nil`，反转这一段链表，然后把 `before.Next` 连接到反转后的头节点，把原来的 `start.Next` 连接到 `after`。最后返回 `dummy.Next`。

下面使用 Go 给出参考实现，语言选择与投递岗位一致；转录无法确认现场代码使用的语言。实现会在修改连接前检查区间是否合法。

```go
type ListNode struct {
	Val  int
	Next *ListNode
}

func reverseBetween(head *ListNode, left int, right int) *ListNode {
	if left < 1 || right < left {
		panic("区间参数不合法")
	}
	dummy := &ListNode{Next: head}
	before := dummy
	for i := 1; i < left; i++ {
		if before.Next == nil {
			panic("区间超出链表长度")
		}
		before = before.Next
	}
	start := before.Next
	end := before
	for i := left; i <= right; i++ {
		if end.Next == nil {
			panic("区间超出链表长度")
		}
		end = end.Next
	}
	after := end.Next
	end.Next = nil

	var prev *ListNode
	curr := start
	for curr != nil {
		next := curr.Next
		curr.Next = prev
		prev = curr
		curr = next
	}
	before.Next = prev
	start.Next = after
	return dummy.Next
}
```

定位和反转最多遍历链表中的线性数量节点，时间复杂度为 `O(n)`；只使用固定数量的辅助指针，额外空间复杂度为 `O(1)`。

**机制分析：** Pipeline 允许客户端连续发送多条命令，随后读取响应，能够减少逐条等待响应带来的 RTT 开销，也可能减少 socket 读写相关开销。一个批次可能通过多个 TCP 数据包传输，实际数量取决于客户端、缓冲和网络条件。批次大小需要考虑命令数量、响应大小和处理时延。[Redis 官方 Pipeline 文档](https://redis.io/docs/latest/develop/using-commands/pipelining/)

Pipeline 中的多条命令之间可能执行其他客户端的命令。对于“读取状态、检查条件、修改状态”的关联逻辑，Lua 可以在服务端执行整个判断和更新过程；脚本执行期间，其他客户端的命令无法插入该过程。脚本应保持短小，并正确传入所访问的 key。[Redis 官方 Lua 文档](https://redis.io/docs/latest/develop/programmability/eval-intro/)

**改进重点：** 准备一条真实请求的完整执行过程，说明进入哪个接口、操作哪些 key、哪些命令进入 Pipeline、哪段条件判断进入 Lua、结果如何处理。性能数据应说明相同请求范围下的平均耗时、P95 或 P99、批次大小和错误率，并区分已测量结果与理论预期。
