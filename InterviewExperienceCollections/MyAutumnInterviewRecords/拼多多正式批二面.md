### 7. HashMap 的实现与并发问题

**当时表现：4.5/10。**

16:47—18:10，你知道数组、链表、红黑树和线程不安全，但把链表长度与数组容量的条件混在了一起，并把头部插入和链表成环的历史问题接在 JDK 8 的结构说明之后。版本与条件需要说明清楚。

**参考回答：**

以 JDK 8 的 HashMap 为例，底层是 Node 数组，发生 hash 冲突时，同一个桶中的元素通过链表或红黑树组织。计算经过扰动处理的 hash 后，使用 `(n - 1) & hash` 确定桶位置；同一个 key 还需要通过相等性判断确认，重复插入会更新 value。

树化涉及桶中的节点数量和整个数组容量两个条件。`TREEIFY_THRESHOLD` 是 8，`MIN_TREEIFY_CAPACITY` 是 64；当插入路径触发树化检查时，数组容量小于 64 会优先扩容。精确到 `putVal` 的普通链表分支，已有 8 个节点时再追加一个新节点，会执行树化检查。全局元素数量超过容量与 load factor 对应的阈值，也会触发扩容。这两种检查应当分别理解。[OpenJDK 8u 的 HashMap 实现](https://raw.githubusercontent.com/openjdk/jdk8u/master/jdk/src/share/classes/java/util/HashMap.java)

HashMap 不提供并发修改保障。多个线程同时插入或扩容，可能造成更新丢失和读取结果不符合预期。JDK 7 中并发扩容、头部插入相关的链表成环问题需要单独说明版本。并发场景可以根据需求使用 ConcurrentHashMap；复合的读取后更新操作，还需要选择 `compute`、`merge` 等合适方法，或使用同步机制。

### 8. 支持随机返回的 KV cache

**当时表现：6.0/10。**

18:10 开始讨论这道题。你知道关键要求是等概率返回 KV，之后在多次提示下逐步形成了数组、位置记录和末尾元素移动的方案。29:10，你自己提出了将目标元素与末尾元素交换后删除，这是一项有价值的推导。需要改进的是更早明确可以使用标准容器，并把“hash 桶下标”和“元素在动态数组中的下标”分别说明。

这道题讨论到 36:33，面试官明确表示暂时不要求编写代码。能够确认的是设计过程与口头说明，转录无法证明已经完成四个操作的现场运行测试。

**参考回答：**

我使用一个连续的动态数组 `entries` 保存当前有效的 KV，再使用一个 hash map `positions` 保存 `key -> entries 中的下标`。数组中的每个 key 只出现一次，并且有效元素连续分布在 `[0, size)`。

插入新 key 时，把 KV 添加到数组末尾，并记录下标；如果 key 已经存在，直接更新对应 value。查询时，通过 `positions` 找到下标，再读取数组。删除时，用末尾 KV 覆盖待删除位置，更新被移动 key 的下标，再删除数组末尾和目标 key 的映射。

random 时，在 `[0, size - 1]` 中等概率产生一个整数，返回对应 KV。当前每个有效 KV 恰好占据一个下标，因此每个 KV 的返回概率都是 `1 / size`。

**复杂度边界：**hash map 查询、插入和删除通常按平均 O(1) 分析，动态数组追加按摊还 O(1) 分析。整个方案达到面试常用的平均或摊还 O(1) 要求；普通 hash map 的冲突、rehash 和动态数组扩容，都需要在追问严格最坏复杂度时说明。代码使用 int 类型的 key 和 value，相关计算与复制按常数成本分析。

**接口约定：**`insert` 更新已经存在的 key，并返回本次是否新增；`get` 对缺失 key 返回空的 optional；`remove` 返回是否删除成功；空容器调用 `random` 直接抛出异常。本题的核心要求没有给出容量、过期时间和淘汰策略。

**C++17 参考代码：**

```cpp
#include <cstddef>
#include <optional>
#include <random>
#include <stdexcept>
#include <unordered_map>
#include <utility>
#include <vector>

class RandomKVCache {
private:
    std::vector<std::pair<int, int>> entries_;
    std::unordered_map<int, std::size_t> positions_;
    std::mt19937 generator_{std::random_device{}()};

public:
    bool insert(int key, int value) {
        auto it = positions_.find(key);
        if (it != positions_.end()) {
            entries_[it->second].second = value;
            return false;
        }
        positions_.emplace(key, entries_.size());
        entries_.emplace_back(key, value);
        return true;
    }

    std::optional<int> get(int key) const {
        auto it = positions_.find(key);
        if (it == positions_.end()) {
            return std::nullopt;
        }
        return entries_[it->second].second;
    }

    bool remove(int key) {
        auto it = positions_.find(key);
        if (it == positions_.end()) {
            return false;
        }
        const std::size_t index = it->second;
        const std::size_t last = entries_.size() - 1;
        if (index != last) {
            entries_[index] = entries_.back();
            positions_.at(entries_[index].first) = index;
        }
        entries_.pop_back();
        positions_.erase(it);
        return true;
    }

    std::pair<int, int> random() {
        if (entries_.empty()) {
            throw std::out_of_range("cache is empty");
        }
        std::uniform_int_distribution<std::size_t> distribution(
            0, entries_.size() - 1);
        return entries_[distribution(generator_)];
    }

    std::size_t size() const {
        return entries_.size();
    }
};
```

`std::uniform_int_distribution` 用来按均匀分布选择合法下标。等概率性质来自下标与当前 KV 的一一对应，以及均匀整数抽样；有限次数的频率检查只能辅助发现明显问题。

### 9. 使用 set 随机选择的问题

**参考回答：**

`std::set` 的迭代器不支持通过任意整数直接定位第几个元素。产生随机整数 i 之后，如果从 `begin()` 开始移动 i 次，访问成本是 O(i)，最坏需要 O(N)。`std::unordered_set` 同样没有按排名进行常数时间访问的接口。

这道题可以用 `std::vector` 保存当前有效元素，通过 `entries[i]` 直接访问随机下标。set 擅长维护自己的集合操作，但这里还需要满足按随机下标访问的要求。

**改进方法：**设计前写出每个操作需要的能力，分别检查容器的查询、插入、删除、下标访问成本。容器中存在 N 个元素，并不能自动推出能够 O(1) 找到第 i 个元素。

### 14. 最小堆方案的复杂度

**当时表现：6.0/10。**

37:25—39:25，你最初的复杂度表达不准确。在面试官追问堆大小后，你给出了 `K × N × log K`。能够根据提示修正，但需要把元素数量和单次操作成本同时说清楚。

**参考回答：**

总共有 M = K × N 个输入元素。堆中每个数组最多保存一个候选元素，因此堆大小最多是 K。每个输入元素最多加入堆一次、取出堆一次，单次调整成本是 O(log K)，所以在 K 至少为 2 时，通常写成 O(KN log K)。

覆盖 K 为 0、K 为 1 和空数组时，可以写为 O(K + M log(K + 1))。扫描输入数组需要 O(K)，堆的空间是 O(K)。保留全部元素时结果空间是 O(M)，去重后的结果空间是 O(U)，其中 U 是不同数字的数量。

去重比较本身只需要 O(1)，但重复元素仍然需要从堆中取出并推进所属数组，因此最坏时间复杂度保持不变。若使用逐个插入完成堆初始化，其成本至多为 O(K log K)，已经包含在上述总成本中。

**当时表现：6.5/10。**

40:17，你询问是否可以改为 K 个链表。面试官要求继续使用数组输入输出。之后你能继续编写，但对数组来源、当前位置和容器方法的组织存在停顿。转录没有完整的屏幕代码，因此无法逐行核验现场实现。

**参考回答：**

函数接收 `const vector<vector<int>>& arrays`，返回 `vector<int>`。外层下标表示数组编号，内层下标表示当前数字的位置。最小堆节点使用 `tuple<int, size_t, size_t>`，分别记录 value、row 和 column。每次取出节点后，用 row 和 column 找到同一数组的下一项。

`removeDuplicates` 控制是否去重，默认保留重复数字。面试现场要求去重时，调用 `mergeSortedArrays(arrays, true)`。输入数组应当已经按非递减顺序排列；函数也支持空数组和各数组长度不同的情况。

**C++17 参考代码：**

```cpp
#include <cstddef>
#include <functional>
#include <queue>
#include <tuple>
#include <vector>

std::vector<int> mergeSortedArrays(
    const std::vector<std::vector<int>>& arrays,
    bool removeDuplicates = false) {
    using Node = std::tuple<int, std::size_t, std::size_t>;
    std::priority_queue<Node, std::vector<Node>, std::greater<Node>> heap;

    for (std::size_t row = 0; row < arrays.size(); ++row) {
        if (!arrays[row].empty()) {
            heap.emplace(arrays[row][0], row, 0);
        }
    }

    std::vector<int> result;
    while (!heap.empty()) {
        auto [value, row, column] = heap.top();
        heap.pop();

        if (!removeDuplicates || result.empty() || result.back() != value) {
            result.push_back(value);
        }

        const std::size_t next = column + 1;
        if (next < arrays[row].size()) {
            heap.emplace(arrays[row][next], row, next);
        }
    }
    return result;
}
```

`std::greater<Node>` 让较小的 tuple 位于堆顶，首先比较 value；值相同时按后两个字段确定顺序。比较过程不使用两个 int 相减，因此能够处理 `INT_MIN` 和 `INT_MAX`。

### 21. CPU 的 L1、L2、L3 cache

**当时表现：2.5/10。**

52:34—53:49，你能够回忆起多级缓存和未命中的概念，但没有说明 CPU 与主存之间的访问延迟差异、程序局部性，以及容量与访问速度的取舍。回答较长时间停留在回忆过程，尚未形成完整解释。

**参考回答：**

CPU 执行指令的速度很快，访问主存的延迟相对较高。如果程序频繁等待主存提供数据，CPU 的执行能力就难以充分利用。cache 使用更快的存储，把近期可能继续使用的数据和指令保存在靠近 CPU 的位置，降低平均访问时间。

以常见的多核 CPU 为例，L1 容量较小、延迟较低，通常分成指令缓存和数据缓存；L2 容量更大，访问延迟也更高，通常属于单个核心；L3 容量进一步增加，通常由多个核心共享。具体容量和共享范围需要结合处理器型号确认。[Intel 的内存性能说明](https://www.intel.com/content/www/us/en/developer/articles/technical/memory-performance-in-a-nutshell.html)

缓存能够发挥作用，依赖程序访问的局部性。时间局部性表示刚使用过的数据，近期可能再次使用；空间局部性表示访问一个地址后，附近地址也可能很快被访问。例如顺序遍历数组时，相邻元素通常可以利用同一次 cache line 读取。

多级设计是在访问延迟、容量、芯片面积和成本之间取舍。较小的 L1 满足高频访问，更大的 L2、L3 保存更多可能使用的数据，降低访问主存的频率。CPU 可以访问主存，只是频繁等待主存会影响性能。

按常见的读访问过程理解，L1 未命中后查询下一层，后续 cache 都未命中时才需要从主存取得数据。实际处理器还会使用预取、并行执行和一致性机制，具体请求路径会随型号变化。

**改进重点：**能够使用“访问延迟差异、局部性、多级容量与速度取舍”连续解释设计原因，再介绍 L1、L2、L3 的常见组织。
