### 8. MySQL 有哪些事务隔离级别？InnoDB 默认使用哪一种？

**时间：**10:44—11:05。

**考察内容：**隔离级别与脏读、不可重复读、幻读的关系。

**你的回答与评分：6/10。**列出了四种隔离级别，并说出 InnoDB 默认使用可重复读。隔离级别的具体行为没有展开，部分英文名称存在转录噪声。

**参考回答：**四种隔离级别是 `READ UNCOMMITTED`、`READ COMMITTED`、`REPEATABLE READ` 和 `SERIALIZABLE`。InnoDB 默认使用 `REPEATABLE READ`，实际连接仍需要检查配置。

`READ UNCOMMITTED` 可能读到其他事务未提交的数据；`READ COMMITTED` 每次一致性读使用新的快照，因此同一事务内两次读取可能得到不同结果；`REPEATABLE READ` 的一致性读复用同一快照；`SERIALIZABLE` 提供更强的隔离，并增加并发执行的限制。InnoDB 在可重复读下还通过相应的范围锁机制处理范围修改中的并发插入问题，具体行为取决于 SQL、索引和读取方式。[MySQL 隔离级别官方说明](https://dev.mysql.com/doc/refman/8.4/en/innodb-transaction-isolation-levels.html)。

**改进重点：**每种隔离级别准备一个两事务时间顺序例子，并能够说明快照读取与加锁读取的差别。

### 9. REPEATABLE READ 下的 MVCC 如何实现？

**时间：**11:26—12:05。

**考察内容：**历史版本、Read View、版本可见性与事务读取方式。

**你的回答与评分：2/10。**回答转向 ACID、undo log、redo log 和锁机制，没有说明 Read View、历史版本链和可见性判断，因此核心问题没有回答清楚。你提到了相关知识，但知识之间的联系还需要补习。

**参考回答：**MVCC 通过保存行的历史版本，让普通查询按照自己的 Read View 读取可见数据。InnoDB 记录中的 `DB_TRX_ID` 表示最近修改这条记录的事务，`DB_ROLL_PTR` 可以关联 undo log，从而重建修改之前的数据版本。[InnoDB 多版本官方说明](https://dev.mysql.com/doc/refman/8.4/en/innodb-multi-versioning.html)。

Read View 包含创建时活跃事务的信息和事务 ID 边界。读取某个版本时，会结合修改者事务 ID、是否为当前事务及活跃事务集合判断可见性；当前版本不可见，就继续寻找可见的历史版本。通常，RR 在第一次一致性读时建立快照，后续一致性读复用它；RC 每次一致性读建立新快照。当前事务自己的修改对自己可见。[MySQL 一致性读官方说明](https://dev.mysql.com/doc/refman/8.4/en/innodb-consistent-read.html)。

例如初始余额为 100，A 在 RR 下读取到 100，B 随后修改为 80 并提交；A 再次进行普通一致性读，仍然读取此前快照中的 100。A 执行 `SELECT ... FOR UPDATE` 或修改语句时，则涉及当前数据和加锁机制，需要单独分析。

**改进重点：**能够画出版本关系并口述一次可见性判断；分别解释 undo log、redo log、Read View 和锁各自的用途。

**参考回答，按三数之和候选题给出：**假设题目要求从整数数组中找出所有和为零且数值组合不重复的三元组，先排序，再枚举第一个元素 `nums[i]`，剩余范围使用 `left`、`right` 两个指针。总和小于零时增加 `left`，大于零时减少 `right`，等于零时记录答案并移动两个指针，跳过相同数值。枚举位置也要跳过重复值。

排序后，对于固定的 `i`，增大 `left` 会使总和不减少，减小 `right` 会使总和不增加，因此可以按总和决定移动方向。枚举复杂度为 O(n²)，排序需要 O(n log n)。本代码按值接收数组，复制输入需要 O(n) 额外空间；常见 `std::sort` 实现还需要 O(log n) 递归空间，输出空间取决于答案数量。求和使用 `long long`，避免三个 `int` 相加溢出。

**练习代码：**以下输入输出格式为学习时约定：输入 `n` 和随后 `n` 个整数，输出三元组数量及各组数值。原题的接口和输入输出要求无法从转录恢复。

```cpp
#include <algorithm>
#include <array>
#include <iostream>
#include <stdexcept>
#include <vector>

std::vector<std::array<int, 3>> threeSum(std::vector<int> nums) {
    std::sort(nums.begin(), nums.end());
    std::vector<std::array<int, 3>> result;
    const int n = static_cast<int>(nums.size());

    for (int i = 0; i + 2 < n; ++i) {
        if (i > 0 && nums[i] == nums[i - 1]) {
            continue;
        }
        if (nums[i] > 0) {
            break;
        }

        int left = i + 1;
        int right = n - 1;
        while (left < right) {
            const long long sum = static_cast<long long>(nums[i])
                + nums[left] + nums[right];
            if (sum < 0) {
                ++left;
            } else if (sum > 0) {
                --right;
            } else {
                result.push_back({nums[i], nums[left], nums[right]});
                ++left;
                --right;
                while (left < right && nums[left] == nums[left - 1]) {
                    ++left;
                }
                while (left < right && nums[right] == nums[right + 1]) {
                    --right;
                }
            }
        }
    }
    return result;
}

int main() {
    std::ios::sync_with_stdio(false);
    std::cin.tie(nullptr);

    int n;
    if (!(std::cin >> n) || n < 0) {
        throw std::runtime_error("Invalid array length");
    }
    std::vector<int> nums(n);
    for (int& value : nums) {
        if (!(std::cin >> value)) {
            throw std::runtime_error("Invalid array element");
        }
    }

    const auto result = threeSum(nums);
    std::cout << result.size() << '\n';
    for (const auto& triple : result) {
        std::cout << triple[0] << ' ' << triple[1]
                  << ' ' << triple[2] << '\n';
    }
    return 0;
}
```

**必须掌握：**实际涉及的敏感字段、服务边界、访问权限、传输保护、日志脱敏、密钥与数据访问责任，以及地域、发卡行、业务主体各自的含义。PCI DSS 相关内容按照项目实际范围学习。

**练习与验证：**从真实接口选择一个敏感字段，描述它的来源、接收方、保存位置、日志行为、访问校验和测试结果。

**掌握标准：**能够准确说明自己修改了哪项接口或访问条件，哪些安全能力由已有平台提供。

## 表达与项目准备

### 直接回答当前问题

第 9 题直接解释历史版本和 Read View；第 34 题直接解释恢复时读取什么进度、继续执行什么节点。每次回答先确定问题要求的具体动作，再补充相关知识，控制跨主题展开。

### 用执行顺序解释机制

对锁、事务、消息和恢复问题，使用同一套顺序：请求带什么标识、读取什么状态、在哪一步修改、什么条件算成功、失败后从哪里继续。每个回答准备一个正常例子和一个异常例子。

### 为个人项目建立证据记录

每个重点需求记录业务问题、个人职责、主要接口或函数、关键判断、测试方式和已确认结果。指标同时保存样本范围、计算方法和时间。补充学习的方案与原项目已经实现的功能分别记录。

### 练习可以连续说完的答案

自我介绍控制在约一分钟；重点项目准备约两分钟的连续说明；技术追问准备四十五秒至九十秒的直接回答。录下自己的口述，检查是否回答了问题、是否频繁重复、是否使用没有核查的术语，以及是否能够说明关键边界。

面试官明确指出表达问题；本场转录同时显示多个核心机制需要继续理解。表达练习应当结合代码阅读和真实运行验证进行。
